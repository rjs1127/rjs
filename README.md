## v6.90

### 사용자 노출 구조 단순화
- 기존 `분량(단편/장편)` + `게시형태(단일글/다회차)` 조합을 사용자 화면에서 제거
- 사용자에게는 `작품형태`와 `상태` 두 개만 표시
- 작품형태: `단편 / 연재물`
- 상태: `연재중 / 완결`
- 포스트/시리즈/수동묶음은 사용자에게 노출하지 않고 내부 연결 방식으로만 유지

### 사용자 필터
- `분량` 필터 제거
- `게시형태` 필터 제거
- `작품형태: 전체 / 단편 / 연재물` 추가
- `상태: 전체 / 연재중 / 완결` 추가
- 작품형태 또는 상태를 선택하면 출처를 자동으로 POSTYPE으로 적용
- TXT에는 작품형태/연재상태를 억지로 부여하지 않고 목록 형태 칸에는 `TXT`로 표시

### 관리자 작품 등록
- 등록 표에서 `분량 / 게시형태 / 연결` 3개 컬럼 제거
- `작품형태 / 상태`만 직접 관리
- 작품형태: `단편 / 연재물`
- 상태: `완결 / 연재중`
- URL 한 개는 기본 `단편`
- `/series/` URL 또는 URL 여러 개 입력 시 자동 `연재물`
- 내부 연결방식 `post / series / manual`은 URL 기준으로 자동 관리
- 여러 URL 수동묶음과 시리즈 API 최근 발행일 조회는 기존 방식 유지

### 관리자 작품 관리
- 목록에서도 `분량 / 게시형태 / 연결` 컬럼 제거
- `작품형태 / 상태 / 최근 발행일`만 표시 및 수정
- 작품형태와 상태 변경도 `변경사항 시트 동기화`에서 함께 저장
- 기존 Sheet의 `workLength`, `publishType`, `linkType`, `manualUrls` 컬럼은 데이터 호환을 위해 삭제하지 않음

### 호환
- 내부 `publishType=단일글/다회차`는 각각 사용자 `단편/연재물`로 표시
- 내부 `status=연재`는 화면에서 `연재중`으로 표시
- 기존 자료를 강제 마이그레이션하지 않고 신규 등록/화면 구조만 단순화
- 수동 `포스타입 시트 동기화`에서도 내부 연결 필드를 KV에 유지하도록 보강

### 관리자 버전
- `현재 버전 v6.90`

## v6.78

### POSTYPE 시리즈 실제 API 사용
- 브라우저 Network에서 POSTYPE가 실제 시리즈 회차 목록을 불러오는 API 확인
- 형식: `https://api.postype.com/api/v1/series/{seriesId}/posts?sort=publishedAt,desc&sort=createdAt,desc&page=0`
- 기존 HTML/JSON 구조 추측 방식은 1순위에서 제거
- 이제 시리즈 최근 발행일은 POSTYPE 웹앱과 동일한 회차 목록 API를 직접 사용

### 최신화 판정
1. 입력된 `/series/{seriesId}` URL에서 `seriesId` 추출
2. POSTYPE 시리즈 posts API 호출
3. API가 이미 `publishedAt DESC`, `createdAt DESC`로 정렬하므로 현재 시리즈의 첫 번째 `POST` 항목 사용
4. 해당 `feedItem.publishedAt` Unix timestamp를 최근 발행일로 변환
5. 한국 서비스 날짜 경계에 맞춰 KST(+09:00) 기준 `YYYY-MM-DD`로 저장
6. 더 이상 1화/마지막 배열/HTML 링크 순서를 추측하지 않음

### fallback
- API가 일시적으로 실패하거나 회차가 비어 있을 때만 기존 시리즈 HTML 구조화 데이터 방식 사용
- 정상적인 경우 `strategy = series-api-first-post`

- API에서 받은 현재 페이지의 회차 수 확인 가능

- `포스타입 시트 동기화` 실행 시 Google Sheet를 읽은 뒤 기존 `postype:index:v1` KV와 실제 콘텐츠 데이터를 비교

- 여러 행이 바뀌어도 현재 KV가 JSON 하나인 구조이므로 변경 시 전체 값을 1회만 저장
- 변경이 없으면 기존 `syncedAt` 유지

- 변경 여부 확인을 위해 수동 동기화 실행 시 Google Sheet 읽기 1회 + 기존 KV 읽기 1회는 필요함

### 방문 기록 집계형 구조로 변경
- 방문할 때마다 `user_visits`에 새 행을 계속 INSERT하던 방식 중단

- 일별 방문 통계는 `daily_user_metrics` 날짜별 1행만 계속 갱신
- 사용자 수와 방문 기간이 늘어나도 방문 로그 행이 무한 증가하지 않도록 변경
- 기존 원시 방문로그는 최초 관리자 대시보드 조회 시 집계 데이터로 1회 마이그레이션
- 기존 원시 방문로그는 90일을 초과한 행만 관리자 대시보드 조회 시 정리
- 신규 방문은 원시 로그에 더 이상 추가하지 않음

### 관리자 대시보드 조회 최적화
- 사용자 1명마다 여러 서브쿼리를 반복하던 구조 제거
- `user_items`, `user_sessions`를 한 번씩 GROUP BY 집계한 뒤 사용자 목록에 JOIN
- 일별 방문수는 원시 방문로그 전체를 읽지 않고 `daily_user_metrics`의 날짜별 집계값만 조회
- 누적 방문수는 `user_visit_stats` 합계만 조회

### 북마크 / 이어보기 쓰기 최적화
- 북마크 버튼을 빠르게 여러 번 누를 경우 650ms 동안 최종 상태만 서버에 저장하도록 디바운스
- 같은 북마크 상태가 다시 전송되면 D1이 불필요한 UPDATE를 하지 않도록 조건 추가
- 이어보기는 기존처럼 스크롤 중 최대 5분 간격 서버 동기화 유지
- 마지막 서버 저장값과 차이가 거의 없는 진행률은 다시 저장하지 않도록 클라이언트 중복 전송 방지
- 서버에서도 진행률/스크롤/청크 위치가 사실상 동일하면 UPDATE를 생략
- 읽음 전환(95% 이상)은 항상 저장하여 읽음 상태가 누락되지 않도록 유지

### 기존 설정 유지
- `USER_DB` D1 바인딩 그대로 사용

## 패치 배포 원칙

앞으로 각 패치 ZIP에는 다음을 포함합니다.

- 실제 변경된 소스 파일
- `README.md` 변경 이력

다음 파일은 사용자가 명시적으로 요청하지 않는 한 패치 ZIP에 포함하지 않습니다.

- `wrangler.toml`
- `.env`, `.dev.vars`
- `.gitignore`
- 서비스 계정 / 토큰 / 인증정보 관련 파일
- 기타 Cloudflare 배포 설정 파일
