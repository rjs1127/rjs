# Google Drive Archive Site — Change Log

이 README는 패치 버전별 변경사항을 누적 기록합니다.

## v6.25

### 관리자 대시보드
- 관리자 페이지에 `대시보드` 탭 추가
- 최근 14일 기준 일별 회원가입 수 표시
- 로그인 사용자 사이트 방문횟수 일별 표시
- 상단에 `전체 가입자 / 오늘 가입 / 오늘 로그인 사용자 방문 / 누적 로그인 방문` 요약 카드 추가

- 관리자 페이지에 `유저 관리` 탭 추가
- 아이디 검색 기능 추가

- 관리자도 비밀번호 원문은 볼 수 없도록 기존 보안 구조 유지

- `계정 삭제` 기능 추가: 사용자 계정, 세션, 이어보기, 북마크, 최근 조회, 읽음 기록, 방문 기록을 함께 삭제

### 로그인 사용자 방문 기록
- D1에 `user_visits` 테이블을 자동 생성
- 별도 SQL 마이그레이션 없이 기존 `USER_DB`를 그대로 사용
- 로그인 상태로 사이트에 들어온 경우 페이지 로드당 1회 방문 기록
- 동일 페이지에서 기능을 사용한다고 방문횟수가 반복 증가하지 않음

- 북마크 모달에서 각 작품별 `×` 버튼으로 북마크 해제 가능

- 비로그인 사용자에게는 기존 목록 디자인 그대로 표시
- 로그인 직후 계정 기록을 불러오면 목록 상태도 즉시 갱신

### 사용자 기록 API
- 기존 D1 `USER_DB` 구조 그대로 사용
- 최근 조회 개별 삭제 / 전체 삭제 기능 추가

## v6.20

### 간단 계정 / 개인 기록
- 최상단에 `회원가입`, `로그인`, `북마크`, `최근 조회`, `도움말` 버튼 추가
- 회원가입/로그인은 별도 페이지 이동 없이 모달 팝업에서 처리
- 아이디는 영문 소문자/숫자/`_`/`-` 3~20자, 비밀번호는 6~50자
- 로그인 성공 후 180일 유지되는 간단 로그인 토큰을 브라우저에 저장
- 기기를 바꿔도 같은 아이디/비밀번호로 로그인하면 개인 기록을 다시 불러옴
- 비밀번호 원문은 저장하지 않고 salt + SHA-256 해시만 저장
- 로그인 토큰도 서버 DB에는 원문 대신 SHA-256 해시로 저장

### 이어보기
- 비로그인 상태에서는 이어보기 위치를 계정 기록으로 저장하지 않음
- 로그인 상태에서는 스크롤 위치/긴 파일 chunk 위치를 사용자 계정에 저장
- 일반 파일은 `scrollTop + 진행률`, 810KB 이상 긴 파일은 `chunk 번호 + chunk 내부 위치 + 진행률` 저장
- 뷰어를 닫을 때 즉시 동기화하고, 장시간 읽는 경우 최대 약 5분 간격으로 중간 동기화
- 95% 이상 읽으면 `읽음` 상태 자동 기록
- 다른 기기에서 로그인해도 이어보기 가능

### 북마크 / 최근 조회
- 본문 상단에 `☆ 북마크` 버튼 추가
- 로그인 없이 북마크 버튼을 누르면 로그인 모달 자동 표시
- 최상단 `북마크`를 누르면 계정에 저장된 작품 목록 표시
- 작품을 열면 로그인 사용자에 한해 최근 조회 작품 자동 저장
- 최상단 `최근 조회`에서 최근 열어본 작품 최대 50개 확인 가능
- 북마크/최근 조회 목록에서 작품을 누르면 바로 본문 열기

### 도움말
- 새로고침 오른쪽에 `?` 도움말 버튼 추가
- `이어보기/북마크/최근 조회 작품을 저장하려면 로그인 후 감상해 주세요.` 안내 모달 제공
- 도움말 모달에서 바로 로그인 모달로 이동 가능

### 저장소
- 사용자 데이터 저장에는 Cloudflare D1 사용
- R2는 사용하지 않음
- D1 binding 이름: `USER_DB`
- 별도 SQL 실행 없이 최초 회원가입/로그인 시 필요한 테이블을 자동 생성
- 설정 파일은 패치 ZIP에 포함하지 않음

## v6.19

### 810KB 이상 긴 파일 렌더링 방식 변경
- 프로그래스바 종료 시간을 늦추는 방식만으로 해결되지 않던 긴 파일 멈춤 현상을 구조적으로 수정
- Google Drive + KV 본문 구조는 그대로 유지하고 R2/유료 저장소는 사용하지 않음
- 810KB 이상 파일은 전체 본문을 한 번에 DOM에 렌더링하지 않도록 변경
- 긴 본문을 브라우저 메모리에서 약 180,000자 단위로 나눔
- 처음에는 앞쪽 1~2개 조각만 화면에 렌더링하여 scrollbar를 빠르게 생성
- 사용자가 실제로 아래로 읽어 내려갈 때 다음 1~2개 조각을 자동 렌더링
- 따라서 프로그래스바가 사라진 뒤 브라우저가 전체 수백만 자 레이아웃을 다시 계산하며 멈추는 구간을 제거
- 추가 본문은 이미 다운로드된 텍스트를 브라우저 메모리에서 표시하므로 Google Drive/KV 추가 요청이 발생하지 않음
- 긴 파일 읽기 위치는 `chunk 번호 + chunk 내부 위치` 기준으로 저장하도록 보완
- 기존 퍼센트 기반 읽기 기록도 이어보기 시 긴 파일의 적절한 chunk 위치로 변환
- 짧은 파일은 기존 전체 렌더링 방식을 유지

## v6.18

### 긴 파일 스크롤 준비 완료 기준 수정
- 810KB 이상 긴 파일에서 프로그래스바가 먼저 사라진 뒤 scrollbar가 뒤늦게 생기던 현상 수정
- 단순 시간 지연 방식이 아니라 실제 `readerPanel.scrollHeight`와 본문 높이를 반복 확인하도록 변경
- 스크롤 영역 높이가 최소 약 0.75초 동안 안정된 경우에만 준비 완료 처리
- 느린 기기에서는 최대 약 9초까지 스크롤 레이아웃 준비를 기다림
- 프로그래스바가 보이는 동안에는 기존처럼 뷰어 스크롤 잠금 유지
- 스크롤 준비가 끝나면 프로그래스바를 유지한 상태에서 먼저 스크롤 잠금을 해제
- 브라우저가 실제 scrollbar를 계산할 수 있도록 2프레임 대기한 뒤 프로그래스바를 제거
- 긴 본문의 높이 계산을 늦출 수 있는 `.reader-content`의 `contain: content`를 해제
- 프로그래스바가 사라지는 시점에는 scrollbar도 이미 사용할 수 있는 상태가 되도록 순서 변경
- R2 관련 기능 없이 기존 Google Drive + KV 구조 그대로 유지

## v6.17

### 긴 파일 로딩 UX 조정
- R2/외부 저장소 구조 변경은 적용하지 않고 기존 Google Drive + KV 본문 구조 유지

- 긴 파일은 본문 렌더링이 끝나도 프로그래스바를 바로 없애지 않고 최소 약 1.7초 동안 유지

- 긴 파일은 프로그래스바가 떠 있는 동안 뷰어 스크롤을 잠금
- 프로그래스바가 완전히 사라진 뒤 자동으로 스크롤 잠금 해제
- 로딩 오류 또는 뷰어 닫기 시에도 스크롤 잠금이 남지 않도록 예외 처리
- 기존 이어보기/처음부터 기능과 v6.15의 분할 렌더링 방식은 그대로 유지

## v6.16

### 수정
- `이어보기 / 처음부터` 버튼이 동작하지 않거나 이동이 체감되지 않는 문제 수정
- 이어보기 버튼 이벤트를 개별 버튼 직접 연결 방식에서 resume 영역 이벤트 위임 방식으로 변경

- `이어보기` 이동 중 발생하는 scroll 이벤트가 저장 위치를 중간값으로 덮어쓰지 않도록 임시 저장 중지 처리
- `처음부터` 선택 시 해당 파일의 읽기 기록을 즉시 삭제하고 최상단으로 이동
- 뷰어를 새로 열어 본문 준비 중에는 읽기 위치 저장을 잠시 중단하여 기존 기록이 0으로 덮이는 문제 방지

## v6.15

### 수정
- 매우 긴 파일에서 로딩 화면이 먼저 사라진 뒤 화면이 멈춰 보이던 문제 수정
- 원인: 첫 본문 조각 수신 시 로딩 DOM을 제거한 뒤 긴 본문 렌더링이 계속 진행되고 있었음
- 로딩 UI와 실제 본문 영역을 분리하여 전체 렌더링이 끝날 때까지 로딩 화면 유지
- 파일 다운로드 단계와 화면 렌더링 단계를 별도로 진행률에 표시
